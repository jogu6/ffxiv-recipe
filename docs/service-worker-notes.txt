Service Worker cache maintenance

- APP_CACHE_VERSION identifies the deployed app shell, including the integrated macro runtime.
  Run npm run cache:app after staging changed assets. The command hashes precached content,
  updates report build identifiers, and retains the existing release number.
- Data-only publication retains the unchanged app-shell identifier as its base
  and adds a stable data suffix derived from app.js and item-icon-pack.js.
  It does not read, rebuild, copy, or update macro runtime artifacts.
- DATA_CACHE_VERSION is separate and must match between the application and Service Worker.
  Image generation also updates PACK_VERSION to identify the expected image-pack content.
- Item.json and the legacy item-ID compatibility mapping use cache-first responses.
  Other same-origin application assets use network-first responses with an offline fallback.
- tips.md and the image-pack download use no-store and bypass Service Worker response caching.
  The image loader separately verifies the pack, caches the verified result through Cache
  Storage or an IndexedDB fallback, and rejects damaged or mismatched cached content.
- Application models and macro consumable lists use generation-specific IndexedDB caches.
  These are separate from the Service Worker's application-shell cache.
- Activation removes obsolete ff14recipe- caches while retaining the current application,
  data, and verified-data caches, then claims clients.
- Same-origin responses handled by the Service Worker receive isolation headers needed by
  the parallel macro engine. A document without active isolation can use the single-threaded
  engine without a forced reload solely to enable shared memory.
- Startup checks for a Service Worker update with updateViaCache set to none before normal
  application interaction. An applied update reloads the application automatically.
- After an update reload, view restoration is skipped once. When the current release requires
  acknowledgement, its notice blocks application use until OK is selected; acknowledgement
  is stored in the browser.
