Service Worker cache maintenance

- Bump APP_CACHE_VERSION in site/sw.js whenever a deployed app-shell file changes, including
  index.html, styles.css, calculation.js, app.js, legal documents, the manifest, or app icons.
- DATA_CACHE_VERSION is separate. Keep it synchronized with the matching constant at the top of
  site/app.js whenever Item.json or public item icons change.
- Item.json and item icons use cache-first behavior. Other app files use network-first behavior.
- tips.md is fetched with no-store and is never cached by the Service Worker.
- Changing APP_CACHE_VERSION installs a new app cache. Activation removes obsolete caches whose
  names begin with ff14recipe-.
- Startup explicitly checks sw.js with updateViaCache set to none and keeps the application inert
  until the check and any activation finish. An applied update reloads automatically.
- After the reload, the current release section from tips.md blocks application use until the user
  acknowledges it with OK. The acknowledged app version is stored locally.
